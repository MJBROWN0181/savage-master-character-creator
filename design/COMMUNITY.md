# Around the Fire, Settings, Bazaar, and Guilds

Keep the approved parchment/forest palette, fantasy artwork, typography, and unobtrusive Bug. Explore remains in the shared header; Settings sits beside it. Appearance uses Follow device by default, with Light and Dark overrides. Profiles use a fixed readable layout, an optional uploaded background, social/shop links, their public posts, and a following list.

Settings contains profile-review status/resubmission, password change/reset, follower preference, making a profile private, friends/blocks, profile export, exact-handle-confirmed profile deletion, billing, and support. A password change verifies the current password, hashes the new password through Convex Auth, and revokes existing sessions. Profile deletion preserves the authentication account and private game data, removes social connections/media/memberships, cancels hosted Guild events, and hides public contributions. Cleanup is bounded and retries in batches. Blocks remain account-level safeguards.

## Campfire feed and sharing

`campfire:page` creates two shuffled public decks from reviewed profiles, applying blocks, removals, follower preferences, and private-Guild exclusions. With both pools available, every six posts contain five followed stories and one discovery. Missing pools fall back to available stories. Small pools cycle. Stoke the Fire changes the seed and restarts the feed; game filters start a new deck. One reactive subscription supplies bounded decks (up to 60 stories per pool), reused by scrolling batches; offscreen cards use browser content visibility. Previously loaded cards remain reachable by scrolling up, and removals/privacy changes apply throughout the rendered feed. Switching community tabs preserves draft forms; signing out clears drafts. Draft stories, ads, and chat warn before leaving the page.

Reposts reference original public posts, so hiding an original also hides its shares. Private Guild messages can only be copied to the public feed by their author after explicit public-sharing consent; the copy contains no private Guild name, chat, or link. Native sharing/copy includes actual post text and a `/p/<postId>` link. Facebook receives that permalink. Sharing opens the user's chosen social app; it does not automatically publish to linked social accounts.

The Vercel handlers `api/share.mjs` and `api/post-card.mjs` read only the unauthenticated public-post query, render escaped text with Open Graph/Twitter metadata, and generate a themed 1200×630 PNG. Private/removed posts return 404 without story metadata. HTML is not cached; images have a 60-second cache, and social platforms may retain their own previews. Helpers live outside `api/` to avoid generating an accidental function. Local Vite routes use the development deployment; production functions default to the production Convex deployment, optionally overridden by server `CONVEX_PUBLIC_URL`. See [Vercel Node functions](https://vercel.com/docs/functions/runtimes/node-js) and [OG image generation](https://vercel.com/docs/og-image-generation).

## Bazaar and Guilds

Bazaar sections: Custom Art, Game Master Hires, Campaigns, One Shots, Maps & Tokens, Books & Accessories, Other. Reviewed, verified members can publish/edit/close/reopen ads with terms, an optional owned validated image (PNG/JPEG/WebP under 4 MB), and an optional HTTPS booking/contact URL. Buyers arrange payment directly with sellers. Images use the existing profile-media validation and ownership checks. Reports enter a private moderation queue. No marketplace checkout is introduced.

A Guild starts forming with its creator and invitations to at least three other reviewed profiles with verified emails. Four distinct accepted profiles and verified email addresses activate chat and scheduling. Official service profiles do not count. This verifies distinct accounts; it does not establish legal identity. Activation is recalculated if someone leaves or loses review. Public directories and active events are visible publicly; chat always requires accepted membership. Private directories are visible only to members and invitees; private events and chat require accepted membership. Founders manage invitations, visibility, and closure. Members schedule events in their local timezone, RSVP, and explicitly share their own messages. Retired Tome creation routes direct users to founding invitations; older Tome content remains readable with its existing membership rules.

## Bug's weekly news

Codex heartbeat automation `bug-s-weekly-game-news` is active for Mondays at 9 AM America/Chicago. It researches official publisher sources for Savage Worlds, Dungeons & Dragons 5e, and Pathfinder 2e, then writes original brief sourced roundups as Bug. No verified new news is stated honestly. Publication uses internal `news:publishWeekly` on production, with an immutable week/game key preventing duplicate posts on retries and a publisher-domain allowlist. It does not deploy or push code. The Codex computer must be available for local automation runs; this is not a server-side cron. Until this implementation is released on production, the automation leaves the feed unchanged and reports that release is needed.

Development Convex has the implementation. Production publishing and social-link routes become available after the next approved GitHub push/deployment. Existing push workflows continue posting Bug's release notes.

Validation covers feed ordering/cycling/blocks, Guild invitation and privacy boundaries, retired endpoint bypasses, event timezones/RSVPs, ownership/review gates, profile cleanup, real hashed-password changes/session revocation, idempotent sourced news, public HTML escaping and private-post rejection, PNG rendering, and account/settings screens. Fixtures run in isolated Convex tests; no real member passwords or profiles are changed.
